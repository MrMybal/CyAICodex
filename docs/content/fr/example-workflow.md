## Exemple : une checklist GitHub partagée {#content}


1. Relisez l’exemple GitHub français ou anglais et adaptez-le au processus réel de publication.
2. Gardez les règles générales en global ; utilisez la portée projet ou type pour les règles spécialisées. Publiez après relecture.
3. Donnez à l’IA de développement une connexion en lecture seule dans la bonne portée avec les globaux utiles.
4. Avant commit ou release, demandez la lecture du Skill, l’examen des vrais fichiers et de l’historique sortants, puis un compte rendu privé.
5. Après une amélioration, demandez explicitement une révision proposée ou enregistrée. Donnez l’écriture à la connexion voulue uniquement, avec la version courante.

Pour un logo : importez l’original approuvé, décrivez le monogramme CY et la transparence à préserver, publiez dans la portée et faites lire règles et original avant une variante.
