# CyDoc migration record — 0.9.0

The former browser manual comprised twenty chapters in English and French, six sample-data JPEG screenshots, four flow diagrams per language, tables, procedural lists and plain code examples. It required the app HTTP server and fetched JSON from /help/content. The replacement is application-owned Markdown built with the pinned CyDoc 0.1.0 package; the whole reader is shipped locally. No CyDoc repository source was modified.

All twenty original page IDs, meaningful ordering, headings, prose, lists, table cells, code samples, image descriptions and diagram node descriptions were migrated. A comparison checked 518 original text values against the compiled export; eight wording updates were reviewed: the help no longer needs the HTTP server, help language follows newly opened views, the print control is now called Print page, and installation troubleshooting refers to the complete _internal/help tree. URL punctuation is preserved in HTML even where the compiler search text inserts whitespace. All six screenshots are byte-identical to their originals.

The export also contains bilingual repository references, release notes, AGPL license context with the authoritative English license text, the developer build guide and Python annotation-based help integration. The translation report is generated by CyDoc. There are 26 pages per language including that report.

The useful connection-guide downloads and get_setup_guide MCP tool remain runtime features and were deliberately retained. The old manual JSON API is retired with HTTP 410 guidance. /help remains a compatibility launcher preserving chapter hashes; the new reader itself is never served there. Menu, tray, F1 and contextual help now request a validated file URL. The old JavaScript/CSS reader and duplicate manual assets have been removed after export, content and launcher checks passed. Installer cleanup removes only those old installed assets, leaving user libraries and unrelated files intact.

Only the image media module is justified. Static flow SVG needs no graph module; no videos, controlled GIFs, 3D meshes or collections exist in this manual. Three.js is absent from host dependencies and from distribution.

The source integration uses the public CyDoc extractComments API on an explicit allowlist containing skills/documentation.py. Python @doc blocks are extracted into both locales and retain source and symbol metadata. No whole-project source index, personal database, credentials or generated diagnostics are distributed.

Known limits: legacy links require the running app and authenticated session to invoke the native launcher; the executable and tray can open help independently of that session. File-origin reading-state persistence depends on the browser. Manual visual verification of file URLs, media controls and keyboard/touch interactions on actual target browsers remains necessary; export checks and DOM fixtures do not prove those behaviors. Non-Windows platforms were not tested. The migration does not add undocumented provider capabilities, automatic translations, semantic Python API indexing or an HTTP documentation service.

See content/en/building-help.md and content/fr/building-help.md for reproducible builds, stable link contracts and revision tracking. See vendor/cydoc/README.md at the repository root for upstream provenance.

## Verification performed

On Windows x64 with Python 3.11.5 and Node.js 22.17.1, npm ci and docs:build/check succeeded. The final export has 52 pages, no missing/outdated/untracked translations, matching EN/FR heading IDs and all required local assets. The complete Python suite passed (79 tests), as did both Node DOM harnesses. PyInstaller and Inno Setup produced the 0.9.0 executable and installer. Two concurrent packaged MCP sessions initialized and read the library; shutdown succeeded. Packaged --open-help --print-help-url resolved English/French page, anchor and media routes; the packaged reader tree is byte-identical to the validated export. Repeated command execution created no _MEI extraction directory. A binary/resource audit inspected 1,268 Python modules and the external resource tree and found no private workspace paths or personal databases/logs.

Native visual, keyboard/touch, file-origin storage and installer execution tests remain manual target checks. The automated export, URL and DOM checks do not establish native browser behavior.
