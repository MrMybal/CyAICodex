## Reuse a reviewed procedure {#content}


1. Read the English or French GitHub starter Skill and adapt it to your actual publication process.
2. Keep generally reusable rules global; use a project/type scope for specialized instructions. Publish after review.
3. Give the development AI a read-only connection with the right scope and global inclusion.
4. Before a commit/release, ask it to read the Skill, inspect the actual outgoing files/history and report privately.
5. After an improvement, explicitly request a proposed or saved revision. Give write access only to the intended connection, using the current version.

For a logo, use the same pattern: import the approved original, specify the CY mark and transparency to preserve, publish in scope, then have the AI read the rules and original before proposing a variant.

{"type": "tip", "title": "Remember", "body": "An example checklist is guidance, not a guarantee of leak-free publishing or blanket permission to push. Apply it to the actual files and release artifacts."}
